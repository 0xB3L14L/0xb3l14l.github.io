Trusted

Created2026-02-13|Updated2026-02-16|VulnlabActive Directory ChainEasy

A port enumeration is started against trusted.vl and lab.trusted.vl.

trusted.vl

lab.trusted.vl (child)

Of the two machines in scope, lab.trusted.vl has a web service and a MySQL database. With this in mind, we can start with this host by performing directory fuzzing.

Several paths are found, with dev being the most interesting.

When visiting that page, it can be seen that the URL loads an index.html file.

There is also a message from the developers.

This message reveals some information:

  • Possible users: Eric and Jack
  • The PHP code is poorly written
  • There is a database

Taking into account how the URL was structured, we can test for LFI. I used Caido for fuzzing, and it produced the following result.

This confirms it is vulnerable to LFI.

Of all the payloads used, db.php was the one that stood out the most, and it may be related to the database mentioned in the message.

MYSQL

After connecting and listing the databases:

There is an uncommon database called news. Inside it there is a table named users.

When listing it:

User names are shown along with their hashed passwords. One of them is Eric, the same name mentioned in the message.

CrackStation can be used to try to crack them.

Only one was successfully cracked:

rsmith

With Robert’s credentials we can test if they work for domain authentication and, if so, look for more users.

And there are only 6 users in the domain.

So the next step is to enumerate with BloodHound, but it was giving issues. dnschef was used to work around this.

When reviewing in BloodHound, it was found that user rsmith has the ability to change ewalters‘ password.

This can be done in several ways; one of them is with BloodyAD, but since it did not work correctly, rpcclient was used instead.

ewalters

User ewalters belongs to the Remote Management Users and Remote Desktop Users groups.

These groups allow the user to connect remotely via both WinRM and RDP.

When enumerating from the root, a folder named AVTest is found.

This folder contains an executable along with a note.

From this we can infer that a program runs automatically.

Additionally, the directory is writable.

This allows renaming the original executable and replacing it with a reverse shell generated with msfvenom.

After waiting a bit, a connection is received as cpowers.

This user belongs to the administrators.

This user is an administrator of the lab.trusted.vl domain; the main domain (trusted.vl) still needs to be compromised, and this can be achieved by becoming Enterprise Admin. One way to do this is through an attack called SID History Attack.

From Domain Admin to Enterprise Admin (SID History Attack)

The trust between domains can be enumerated.

One way to abuse the trust between a child and the main domain is by forging a golden ticket.

First, use Mimikatz to obtain the NT hash of krbtgt.

The SIDs of both domains are also needed.

With all of this, the golden ticket is created. When setting the main domain SID, the RID 519 (Enterprise Admin) must be appended.

Finally, a DCSync attack is performed to dump the NTDS and obtain the main domain Administrator’s hash.

And we gain access to the main domain as admin.

Summary

LFI on /dev → MySQL credentials in db.php → hash cracking (rsmith) → BloodHound + password change for ewalters → WinRM/RDP → replace binary in AVTest with reverse shell → cpowers (Domain Admin on lab.trusted.vl) → SID History / golden ticket with Mimikatz → DCSync against main domain → Administrator on trusted.vl.
