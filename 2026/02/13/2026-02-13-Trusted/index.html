Trusted

Creado2026-02-13|Actualizado2026-02-16|VulnlabActive Directory ChainEasy

Se inicia una enumeración de puertos a trusted.vl y lab.trusted.vl

trusted.vl

lab.trusted.vl (child)

De las dos máquinas del scope, lab.trusted.vl tiene un servicio web, y una base de datos MySQL. Con esto en mente se puede empezar con este host por medio de un fuzzing de directorios.

Se encuentran varios, siendo dev el más interesante.

Al dirigirse a esa página se logra apreciar que en la URL carga un archivo index.html

A su vez, se encuentra un mensaje de los desarrolladores.

Este mensaje revela cierta información:

  • Posibles usuarios: Eric y Jack
  • El código PHP está mal escrito
  • Hay una base de datos

Tomando en cuenta cómo se representaba la URL, se puede probar si es vulnerable a LFI. En mi caso utilicé Caido para hacer el fuzzing, y al terminar dio el siguiente resultado.

Al revisarlo en el navegador

Se demuestra que si es vulnerable a LFI.

De todos los payloads utilizados el que más llamó la atención fue db.php, y este puede estar relacionada con la base de datos mencionada en el mensaje.

MYSQL

Al conectarse y listar las bases de datos.

Hay una DB que no es común llamada news. Y dentro de esta hay una tabla llamada users.

Al listarla.

Se muestran nombres de usuarios junto con sus contraseñas cifradas. Y uno de estos se llama Eric, este mismo nombre se hacía mención en el mensaje.

Con CrackStation se puede intentar crackearlas.

Solo se logra crackear una:

rsmith

Al tener las credenciales de Robert se puede probar sirven para autenticarse en el dominio, y si es así buscar si hay más usuarios.

Y en el dominio solo hay 6 usuarios.

Así que toca enumerar con bloodhound, pero me daba problemas. Y para solventarlo se utilizó dnschef.

Al revisar en BloodHound se descubrió que el user rsmith tiene la capacidad de cambiarle la contraseña al user ewalters

Esto se puede conseguir de distintas maneras, una de ellas es con BloodyAD, pero al no funcionar correctamente se utilizó rpcclient.

ewalters

El usuario ewalters pertenece a los grupos Remote Management Users y Remote Desktop Users.

Estos grupos permiten al usuario conectarse remotamente tanto por winrm como por rdp.

Al enumerar desde la raíz, se descubre una carpeta llamada AVTest.

En esta carpeta hay un ejecutable junto con una nota.

Se puede entender que programa se ejecuta automáticamente.

Además, se puede escribir en el directorio.

Esto permite renombrar el ejecutable original y suplantarlo con una reverse shell generada con msfvenom.

Después de esperar un poco, se recibe una conexión como cpowers.

Este usuario pertenece a los administradores.

Este usuario es administrador del dominio lab.trusted.vl, aún falta comprometer el main domain (trusted.vl) y se lo puede conseguir si logra convertirse en Enterprise Admin. Y una forma de hacerlo es por medio de un ataque llamado SID History Attack.

From Domain Admin to Enterprise Admin (SID History Attack)

Se puede enumerar el trust que existe entre dominios.

Una forma de abusar del trust entre un child y main domain es forjando un golden ticket.

Lo primero, con Mimikatz conseguir el nt hash del krbtgt.

También se necesita el SID de los dos dominios.

Y con todo esto se crea el golden ticket. Al momento de colocar el SID del main domain, se debe agregar el RID 519 (Enterprise Admin).

Por último, se realiza un ataque dcsync para dumpear el ntds y conseguir el hash del Administrator del main domain.

Y se entra en el main domain como admin

Resumen

LFI en /dev → credenciales MySQL en db.php → crack de hashes (rsmith) → BloodHound + cambio de contraseña a ewalters → WinRM/RDP → sustitución del binario en AVTest por reverse shell → cpowers (Domain Admin en lab.trusted.vl) → SID History / golden ticket con Mimikatz → DCSync al main domain → Administrator en trusted.vl.
