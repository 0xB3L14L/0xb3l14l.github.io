Hybrid

Created2026-02-13|Updated2026-02-16|Active Directory ChainVulnlabEasy

The infrastructure consists of a Domain Controller (dc01.hybrid.vl) and a mail server (mail01.hybrid.vl).

dc01.hybrid.vl

Nmap

mail01.hybrid.vl

Nmap

This server exposes mail services (SMTP, POP3, IMAP), HTTP, and an NFS resource.

NFS

We proceed to enumerate the NFS exports.

A resource called /opt/share appears, so a mount is created to view its contents.

Inside there is a compressed file.

Backup

When decompressing it, both gzip and tar show:

And credentials for the users admin and peter.turner are found

IMAPS - Dovecot

With the creds of peter and the admin, you can access the RoundCube mail server, both via terminal and web.

For my own pleasure, I wanted to enter using the terminal.

admin

For this, I used the admin credentials.

Once inside, folder enumeration begins.

No mail was found in Junk and Inbox, so the sent mails are tried.

This email is for Peter, where a new plugin for spam is mentioned.

Since no more information was found, you can go to the website and learn more about that plugin.

peter.turner

HTTP - RoundCube Mail Server

You can log in as admin or peter

Once inside, you can find out the version of RoundCube, and which spam plugin is installed.

Webmail version 1.6.1, and markasjunk (plugin) 2.0

By investigating more about markasjunk 2.0 it turns out it is vulnerable to an RCE.

Roundcube markasjunk RCE

The payload to be used will be the following:

The ${IFS} are separators, and can represent spaces, tabs, or a new line.

This payload should be placed in the Email field, located within Settings and Identities.

Then, a test email is sent and marked as spam.

This will execute the payload, allowing to get a shell.

www-data - Mail Server

Enumerating the server, something interesting is found in /etc/exports

Here, the UID can be abused to escalate privileges, since the file /etc/exports shows that /opt/share has write permissions. With this in mind, the user peter can be impersonated from our attacking machine.

The exploitation steps would be the following:

  1. Create a local user with the same UID.

  2. Mount the NFS resource.

  3. Copy /bin/bash from the server to the NFS resource, and from our machine assign the Sticky Bit (chmod u+s) to it.

  4. From the mail01 server, execute /opt/share/bash -p to get a shell as peter.turner.

So, first the ID of peter.turner is obtained.

The uid is 902601108

Now on our machine, a user is created with that id.

If the error “useradd warning: fake’s uid 902601108 outside of the UID_MIN 1000 and UID_MAX 100000000 range.” appears, you need to modify /etc/login.defs and increase UID_MAX.

With the user created, now mount the NFS resource as this user.

Done, next is to copy the /bin/bash from the server to the NFS resource.

Copy bash to our machine, and remove it from the mount

Finally, move bash back to the mount and add the sticky bit.

Now bash will appear like this

And from the server, execute bash

Thus achieving escalation to peter.turner

peter.turner - mail01.hybrid.vl

No shell - keepass file

Listing the home.

There is a keepass file, it is retrieved and opened.

It asks for a password, which is the same as peter.turner’s that was used for the mail (PeterIstToll!)

Inside, the following is found:

A password appears, which turns out to be peter’s password.

Peter can execute all commands as sudo.

Switch to root and get his flag

But more importantly, with this key you can authenticate to the Domain Controller.

But before going to the other target, you have to keep enumerating the mail server. Especially look for credentials, considering that it is present in an AD environment, you can look for keytab or ccache files.

There is one

Bring it over, and check who the Principal is

It is the computer MAIL01$

With the keytabextract tool, you can get the hash from the keytab.

peter.turner - dc01.hybrid.vl

Nothing was found when enumerating with bloodhound.

Looking for vulnerable cert templates, one appears

The HybridComputers template is vulnerable to ESC1, but it is only available to admins and computers, as they have enrollment rights and Domain Users do not appear in this.

And that is why it is important to properly enumerate the machines even after gaining root, especially if they are on a network. Previously, the nt hash of the computer MAIL01$ was obtained thanks to its keytab.

And with that, it is possible to authenticate as the computer MAIL01$, and therefore exploit ESC1.

ESC1

If at any point you get this error.

You must use -key-size 4096 when generating the certificate.

With the pfx, it authenticates to obtain the admin’s ccache.

And with this, it is possible to access DC01 as Domain Admin.

Summary

RCE in Roundcube (markasjunk plugin) → NFS abuse (UID 902601108 spoofing for Peter Turner) → Creation of binary with Sticky Bit → Escalation to peter.turner → Extraction of KeePass database (passwords.kdbx) → Obtaining NT hash of the MAIL01$ machine account via keytab → AD CS attack (ESC1) on HybridComputers template → Administrator impersonation (SAN UPN/SID) → Domain Admin
